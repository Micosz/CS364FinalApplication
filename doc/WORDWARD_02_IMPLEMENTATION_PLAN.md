# แผนงาน 02 · คลังคำและอันดับความหมายของ Wordward

เอกสารนี้เป็นแผนสำหรับ branch `member/02-words` อ้างอิงโค้ดที่ commit `2ace785` และงาน [Issue #2](https://github.com/Micosz/CS364FinalApplication/issues/2) ฐานมี 14 คำหลักกับ 2 โจทย์ที่เรียงอันดับด้วยมือ ผล 6 unit tests เป็นหลักฐานเดิมของฐาน ส่วนชุดข้อมูลใหม่ ผลตรวจคุณภาพ และผลวัดบน Android เป็นงานที่จะทำในขั้นพัฒนาค่ะ

## 1. เป้าหมายและขอบเขต

เป้าหมายล่าสุดของงาน 02 คือ **คำหลักภาษาอังกฤษ 5,000 คำพอดี และคำลับไม่ซ้ำกัน 31 คำ** คำลับทุกคำอยู่ในคลัง ทุกโจทย์จัดอันดับคำหลักครบชุดเดียวกัน รูปคำหรือ alias ใช้ช่วยให้เดาได้หลายรูปและไม่นับเพิ่มใน 5,000 คำ [ข้อตกลงทีมปัจจุบัน](../docs/team/TEAM_AGREEMENTS.md) ยังอ้าง 1,000 คำ / 31 โจทย์ ให้แจ้งทีมและประสานเกณฑ์ตรวจรับของ Issue ที่เกี่ยวข้องก่อนรวมงาน โดยใช้ 5,000 / 31 เป็นเป้าหมายในแผนนี้

ใช้ความถี่ช่วยคัดคำและใช้เวกเตอร์ที่ฝึกมาแล้วคำนวณอันดับบนคอมพิวเตอร์ล่วงหน้า แอป Java อ่าน TSV ที่มากับแอปและค้นอันดับออฟไลน์ การฝึกโมเดล การใส่เวกเตอร์หรือโมเดลไว้ใน APK การเรียก API การแก้ UI/กติกา/การบันทึกรอบ รวมถึง Give up และสถิติอยู่นอกงาน 02

## 2. ตรวจฐานและแยกข้อมูลทดสอบ

1. ตรวจสถานะและ commit ของ branch ก่อนแก้ ดู [ใบงาน 02](../docs/team/02-words.md), `WordRanker.java`, `puzzles.tsv`, `aliases.tsv` และ `StarterTest.java` เก็บผล build และ tests ที่รันบน branch ตอนเริ่ม เพื่อเทียบกับชุดข้อมูลที่จะเพิ่ม
2. ย้ายข้อมูลตัวอย่าง ocean/apple สำหรับการทดสอบไปเป็น fixture เล็กใน test resources และให้ tests ที่อ้างอันดับเดิมอ่าน fixture นั้น ประสานเจ้าของ tests หากกระทบหลายงาน ชุด production ตรวจแยกด้วย validator และทดสอบผ่าน parser จริง ขนาด fixture ไม่ควรถูกบังคับให้เท่าขนาด production ใน Java parser
3. ตรวจ caller ที่ใช้สัญญาด้านล่างก่อนเปลี่ยน assets ใช้รูปแบบที่อ่านได้ด้วย parser เดิมและเก็บไฟล์ UTF-8 ตามข้อ 5

## 3. คัดคำหลัก คำลับ และรูปคำ

1. ตรึงรุ่น `wordfreq` และวิธีเรียกข้อมูลภาษาอังกฤษ ใช้ความถี่เพื่อสร้างผู้สมัครมากกว่า 5,000 คำและจัดลำดับพิจารณา จากนั้นคัดด้วยเกณฑ์ของเกม เก็บรายการคำที่เพิ่มเอง ตัดออก หรือจำเป็นต้องทบทวน พร้อมเหตุผล เพื่อให้คัดรอบต่อไปซ้ำได้
2. รับคำหลักตัวพิมพ์เล็กตาม `[a-z]+` ที่มีความหมายใช้งานจริง กระจายคำนาม กริยา คำคุณศัพท์ และชนิดคำอื่นข้ามหมวด เช่น บ้าน อาหาร ธรรมชาติ อารมณ์ และการเดินทาง ตรวจชื่อเฉพาะ ชื่อแบรนด์ คำหยาบ คำผิด คำย่อ โทเคนจากเว็บ และคำที่มีแต่รูปผัน อย่าคัดจาก top 5,000 ดิบ เพราะความถี่เพียงอย่างเดียวบอกความเหมาะสมกับเกมไม่ได้
3. คัดเฉพาะคำที่มีเวกเตอร์ใช้ได้จากแหล่งและรุ่นเดียวกัน ตรวจจำนวนมิติ ตัวเลข finite และ norm ที่มากกว่าศูนย์ บันทึกคำที่หาเวกเตอร์ไม่พบหรือเวกเตอร์เสีย แล้วเติมจากผู้สมัครลำดับถัดไปที่ผ่านเกณฑ์และหมวดที่ขาดจนได้ 5,000 คำหลักไม่ซ้ำ หากยังไม่ครบ ให้ขยายผู้สมัครและตรวจใหม่ก่อนส่งออก
4. เลือกคำลับที่คุ้นเคยและมีคำเชื่อมโยงให้เดาต่อได้หลายทางจากคลังสุดท้าย ให้มี 31 คำต่างกัน กระจายหมวดและความยาก ตรึงเป็นรายการตามลำดับในไฟล์อินพุตที่ตรวจ diff ได้ ถ้าใช้การสุ่มตอนจัดลำดับ ให้ตรึง seed และส่งมอบรายการผลลัพธ์ด้วย
5. ทำ alias จากรูปผันที่ตรวจแล้ว เช่น `apples → apple` และ `children → child` เมื่อเป้าหมายอยู่ในคลัง ใช้หลักฐานพจนานุกรมหรือรายการที่ตรวจด้วยคน งดการตัด `s` แบบเหมารวม และเก็บคำพ้องความหมายเป็นคำเดาแยกกัน ตรวจการชนกับคำหลัก คีย์ซ้ำ รูปกำกวม การชี้หากัน และเป้าหมายที่ไม่มีจริง กรณีกำกวมให้บันทึกเหตุผลหรือเว้น alias นั้นไว้

## 4. สร้างอันดับบนคอมพิวเตอร์

1. เลือก pretrained GloVe เช่น Wikipedia 2014 + Gigaword 5 รุ่น 6B ไฟล์ 100 มิติภายใน archive `glove.6B.zip` ตรวจชื่อไฟล์ มิติ และ SHA-256 ของสิ่งที่ดาวน์โหลดจริงก่อนเริ่ม ใช้เวกเตอร์ที่ฝึกมาแล้วและอ่านเฉพาะคำที่ต้องใช้ [รายการ pretrained GloVe](https://github.com/stanfordnlp/GloVe/blob/master/README.md)
2. สำหรับแต่ละคำลับ หาคะแนน cosine ของเวกเตอร์คำลับกับทุกคำในคลัง ใช้ dot product หารด้วยผลคูณของ norm หรือ normalize เวกเตอร์ก่อนแล้วใช้ dot product เก็บการตั้งค่าที่มีผลต่อคะแนน เช่น precision และวิธีคำนวณ ไว้กับสคริปต์
3. วางคำลับที่ #1 เพียงครั้งเดียว แล้วเรียงคำอื่นตามคะแนนจากสูงไปต่ำ กำหนดเกณฑ์ตัดสินคะแนนเท่ากันเป็นลำดับตัวอักษร ASCII หากปัดคะแนนก่อนเรียงเพื่อความคงที่ ให้ตรึงจำนวนหลักและบันทึกไว้ก่อนตรวจคุณภาพ สร้างซ้ำแล้วเทียบ hash ของ TSV โดยใช้รุ่นอินพุต สคริปต์ และสภาพแวดล้อมเดียวกัน
4. ให้คนตรวจ **20–50 อันดับแรกของทั้ง 31 โจทย์** บันทึกจำนวนที่ตรวจต่อโจทย์และข้อสังเกต เกณฑ์คือคำที่เกี่ยวควรปรากฏใกล้หัวตาราง มีทางไล่เดาหลายแบบ คำที่ดูหลุดต้องทบทวน รวมถึงความหมายที่สองของคำเดียวกัน อคติจากแหล่งฝึก คำไม่เหมาะสม ความยาก และความครอบคลุมของหมวด ลองเทียบคู่คำที่คาดไว้ เช่น `sea` ควรใกล้ `ocean` กว่า `pencil` เมื่อใช้โจทย์นี้ คะแนน cosine วัดความคล้ายตามข้อมูลฝึก จึงใช้การเล่นจริงประกอบก่อนรับชุดคำ หากเปลี่ยนรายการ ให้สร้างและตรวจใหม่พร้อมบันทึกเหตุผล

## 5. รูปแบบไฟล์และสัญญากับ Java

| ไฟล์หรือเมธอด | สัญญา |
|---|---|
| `app/src/main/assets/puzzles.tsv` | 31 บรรทัด ลำดับบรรทัดคือลำดับโจทย์ แต่ละบรรทัดเป็น `secret<TAB>secret word2 word3 ...` หลัง TAB มีคำหลักไม่ซ้ำครบ 5,000 คำ คั่นด้วยช่องว่าง และชุดคำตรงกันทุกบรรทัด |
| `app/src/main/assets/aliases.tsv` | แต่ละบรรทัดเป็น `form<TAB>canonical` ใช้คีย์รูปคำไม่ซ้ำ ไม่ชนคำหลัก และชี้ไปยังคำหลักโดยตรง |
| `WordRanker(InputStream, InputStream)` | อ่านทั้งสอง TSV แบบ UTF-8 ด้วย parser เดิม ไม่มีหัวตาราง บรรทัดว่าง หรือ BOM ในไฟล์ข้อมูล |
| `canonical(input)` | สำหรับสตริงอินพุต ตัดช่องว่างหัวท้าย แปลงเป็นตัวพิมพ์เล็กแบบ `Locale.ROOT` คืนคำหลักหรือ `null` เมื่อค้นไม่พบ |
| `daily()` และ `rankFor(secret)` | คืนลำดับคำลับตามไฟล์ และตารางของคำลับที่ร้องขอตามลำดับ |
| `Ranking.rank(word)`, `size()`, `wordAt(rank)` | รับคำหลักที่รู้จักและอันดับที่อยู่ในช่วง ใช้อันดับแบบเริ่มที่ 1 ทุกคำต้องย้อนกลับได้จาก `wordAt(rank(word))` |

`<TAB>` ในตารางหมายถึงอักขระแท็บจริง ใช้ LF และจบไฟล์ด้วย newline ใส่ข้อมูลใบอนุญาตและ metadata ในไฟล์ประกอบ เพื่อให้สอง TSV ตรงตาม parser

## 6. ประสานกับเจ้าของส่วนอื่น

- **งาน 04** รับรายการคำลับ 31 คำตามลำดับที่ตรึงแล้ว วันเริ่มจริง การเล่นก่อนวันเริ่ม และพฤติกรรมหลังวันที่ 31 รอทีมยืนยัน การวนกลับตาม `floorMod` ในฐานคือพฤติกรรมเดิม ยังไม่มีข้อสรุปสำหรับชุดใหม่ ข้อมูลคำทั่วไปสำหรับคำใบ้เป็นข้อเสนอเพิ่มเติม ให้ตกลงรูปแบบและผู้ใช้ข้อมูลก่อนเพิ่ม โดยคงสัญญา `Ranking` เดิม
- **งาน 05** รับรหัสรุ่นชุดข้อมูลและ hash เพื่อกำหนดวิธีจัดการเซฟเก่า การเปลี่ยนสมาชิกคลัง ลำดับโจทย์ หรืออันดับควรมีรุ่นใหม่ งาน 05 ดูแล `GameActivity` การเปลี่ยนวัน การโหลด/แสดงสถานะ การบันทึก และการแก้ไฟล์ build หากจำเป็น งาน 02 ส่งผลวัดและข้อมูลประกอบให้คน 5
- **งาน 01/03/05** รับผิดชอบปุ่มและ callback ยืนยัน กติกาการเริ่มรอบใหม่ และการเขียนเซฟตามลำดับ งาน 02 ต้องรับประกันว่าเริ่มใหม่ในวันเดิมและรุ่นข้อมูลเดิมแล้วได้ **คำลับและอันดับชุดเดิม** งาน 01 เป็นเจ้าของ UI และงาน 03 เป็นเจ้าของกติกาการเดาและนับครั้ง

## 8. เกณฑ์ตรวจรับและสิ่งส่งมอบ

- [ ] Validator ตรวจ 5,000 คำหลัก 31 คำลับ และ 5,000 อันดับในทุกบรรทัด ตรวจสมาชิกชุดคำตรงกัน คำลับอยู่ในคลังและเป็น #1 เสมอ ลำดับคำลับตรงรายการที่ตรึง ไม่มีคำซ้ำหรือคำตกหล่น และ alias ทุกตัวชี้เป้าหมายถูกต้อง
- [ ] Unit tests โหลดชุดเล็กและชุดจริงผ่าน parser เดิม ตรวจอันดับกลับทางครบทุกอันดับ รวม #1 และ #5000 ตรวจ uppercase, ช่องว่าง, พหูพจน์, คำนอกคลัง และชุด TSV เสีย เช่น TAB ผิดรูป คำซ้ำ สมาชิกขาด/เกิน หัวบรรทัดผิด และ alias ชนกัน แยกกรณีที่ validator ปฏิเสธออกจากกรณีที่ Java โยน `IOException`

- [ ] วัดบน Android จริงหรือ Emulator โดยบันทึกรุ่นเครื่อง/API และ build ที่ใช้ จับเวลาเปิดจาก cold start แยกเวลา parse/load assets บันทึก memory ก่อนและหลังโหลดหรือ peak ที่วัดได้ ขนาดไฟล์และ APK และลองพิมพ์/กดปุ่มขณะโหลด ตรวจเปิดแอปแล้วเดาในโหมดเครื่องบิน พร้อมทดสอบเริ่มรอบวันนี้ใหม่ร่วมกับงาน 01/03/05 ระบุสิ่งที่เห็นและข้อมูลวัดจริงก่อนสรุปผล จำนวน `31 × 5,000 = 155,000` คือจำนวนอันดับในตาราง ไม่ใช่ผลวัดเวลา
