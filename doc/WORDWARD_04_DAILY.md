## กติกาคำใบ้ที่ใช้จริง

ให้ N = `ranks.size()` และ best = `round.best()`:

1. รอบจบแล้ว, best <= 2 หรือ N < 2: คืน `null`
2. ยังไม่มีประวัติ: เลือกช่วงประมาณ 50–75% ของ N เช่น N=1,000 ใช้ #500–750 และ N=5,000 ใช้ #2500–3750 บีบขอบให้อยู่ใน 2..N สำหรับคลังเล็ก
3. มีประวัติแล้ว: เลือกช่วง floor(0.8 × best)..floor(0.9 × best) โดยอยู่ภายใน 2..min(N, best−1) เมื่อใกล้คำตอบใช้ช่วงที่ยังเหลือ เช่น best #3 ให้ #2 ได้
4. รับเฉพาะคำที่ไม่เคยเห็นและผ่านตัวกรอง แล้วเลือกด้วย `Random` ที่ส่งเข้าตัวสร้าง การใช้ seed เดิมกับประวัติและข้อมูลเดียวกันให้ลำดับเดิม
5. หากไม่มีผู้สมัครในช่วงเป้าหมาย ให้ขยายออกด้านละประมาณ 10% ของ N สำหรับครั้งแรก หรือ best สำหรับครั้งถัดไป ขยายอย่างน้อยครั้งละ 1 อันดับจนเต็มขอบเขตที่อนุญาต ไม่ข้ามไปเลือกคำใกล้เฉลยทันที หากยังไม่มีคำใช้ได้คืน `null`

ช่วงเดิมหลังมีประวัติคือประมาณ 80%..best−1 เช่น best #100 อาจได้ #99 การจำกัดเป้าหมายใหม่เป็น #80–90 ทำให้ขยับเข้าใกล้คำตอบได้ชัดขึ้น ตัวอย่างอันดับ 1,000–5,000 ของสเปกเก่าไม่ได้ถูกนำมาใช้เป็นขอบเขตตายตัว

### จุดรับข้อมูลคำทั่วไปสำหรับงาน 02/05

เพิ่ม overload ที่รักษาการเรียกใช้เดิม:

```java
HintEngine engine = new HintEngine(new Random(364), commonWords::contains);
String hint = engine.next(round, ranks);
```

`commonWords` ในตัวอย่างคือชุด **คำหลัก canonical** ที่งาน 02/05 ต้องตกลงและจัดเตรียม ไม่ใช่ alias ตัวกรองต้องให้ผลคงที่ระหว่างเลือกคำและไม่เปลี่ยนรอบ งาน 03/05 ยังคงเป็นผู้เพิ่ม entry/นับยอด/บันทึกหลังได้รับคำ

ตอนนี้แอปยังใช้ constructor เดิม ซึ่งยอมรับคำในคลังทุกคำ ยังไม่มีข้อมูล common-word จริงจากงาน 02 และไม่มีการอนุมานรายการคำทั่วไปจากอันดับความใกล้เคียง tests ของตัวกรองใช้เงื่อนไขจำลองเพื่อตรวจกลไกเลือก/ขยายช่วงเท่านั้น

### หลังเริ่มรอบวันนี้ใหม่

HintEngine ไม่เก็บ best หรือประวัติไว้ภายใน เมื่อได้รับ GameRound ว่างของวันและโจทย์เดิม จะใช้กติกาคำใบ้ครั้งแรกอัตโนมัติ แม้ engine เดิมจะเคยถูกใช้ในรอบที่ชนะแล้ว

test สร้างรอบว่างใหม่เพื่อตรวจสัญญานี้ เมธอด reset ของงาน 03 และปุ่ม/การเขียนเซฟของงาน 01/05 ยังไม่ได้เชื่อมในรอบงานนี้ จึงไม่อ้างว่าผ่านการทดสอบรีเซ็ตทั้งแอปแล้ว

## ข้อเสนอ dialog เริ่มใหม่ค้างข้ามเที่ยงคืน · รอคน 01/05 ยืนยัน

ข้อเสนอเพื่อป้องกันคำว่า “วันนี้” บน dialog เดิมไปลบรอบวันใหม่:

1. เมื่อเปิด dialog ให้จำวันที่/รหัสโจทย์และรุ่นข้อมูลของรอบที่กำลังยืนยัน
2. เมื่อกดยืนยัน ตรวจวันไทยและรอบปัจจุบันอีกครั้งก่อนลบข้อมูล
3. ถ้ายังเป็นรอบเดิม จึง reset และบันทึกรอบว่างตามสัญญาของงาน 03/05
4. ถ้าวันหรือรอบเปลี่ยนแล้ว ให้ยกเลิกการยืนยันเก่า refresh เป็นโจทย์ปัจจุบัน และแจ้งว่าโจทย์เปลี่ยนวันแล้ว ให้ผู้ใช้เปิด dialog ใหม่หากต้องการเริ่มรอบใหม่ ห้ามใช้คำยืนยันเดิมลบรอบใหม่โดยอัตโนมัติ

รายการให้คน 01/05 ทดสอบเมื่อยืนยันนโยบายแล้ว:

- เปิด dialog ก่อน 00:00 ไทย แล้วยกเลิก: ไม่ล้างรอบใด
- เปิดก่อน 00:00 และยืนยันก่อนเปลี่ยนวัน: ล้างเฉพาะรอบที่ยืนยัน ใช้โจทย์เดิม ภาษา/ธีมคงเดิม
- เปิดก่อน 00:00 และยืนยันหลังเปลี่ยนวัน: ตรวจจับคำยืนยันเก่าและไม่ลบรอบวันใหม่
- แอปเปิดค้างผ่านเที่ยงคืนหรือกลับจาก background: แสดงโจทย์ของวันใหม่ตามวันไทย โดยไม่รับคำเดา/คำใบ้เข้าอันดับของวันก่อน
- หลัง reset แล้วปิด/เปิดแอป: ประวัติที่ลบไม่กลับมา และคำใบ้ใช้กติกาครั้งแรกของรอบใหม่

รายการข้างต้นเป็นข้อเสนอและกรณีตรวจสำหรับจุดเชื่อม ไม่ใช่ผลทดสอบ UI ที่ผ่านแล้ว
